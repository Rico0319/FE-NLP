Technical Manuscript: Data Extraction, Cleaning, and Control Variable Construction for S&P 500 AI Disclosure Project

1. 10-K MD&A Data Extraction from SEC EDGAR

1.1 Data Source and Scope

The project required MD&A (Management's Discussion and Analysis) sections from S&P 500 companies' 10-K filings for fiscal years 2019-2025. The SEC EDGAR API provides programmatic access to these filings through the https://www.sec.gov/Archives/edgar/ endpoint.

Key constraints:

  • SEC enforces a rate limit of 10 requests per second
  • Each company-year requires downloading the full 10-K filing HTML
  • Filings come in multiple formats: plain text, HTML, and XBRL
  • The accession number format is CIK-year-sequence (e.g., 0000002488-19-000011)

1.2 Python Implementation

The extraction used Python's requests library with proper User-Agent headers (required by SEC):

import requests
from bs4 import BeautifulSoup
import time

HEADERS = {'User-Agent': 'Columbia University Research rico.zhu@columbia.edu'}

def download_10k(cik, accession_number):
    """Download a single 10-K filing from SEC EDGAR."""
    # Clean accession number (remove dashes for URL)
    acc_clean = accession_number.replace('-', '')
    
    # Construct URL: https://www.sec.gov/Archives/edgar/data/CIK/ACCESSION/filing.txt
    url = f"https://www.sec.gov/Archives/edgar/data/{int(cik)}/{acc_clean}/{accession_number}.txt"
    
    response = requests.get(url, headers=HEADERS)
    time.sleep(0.1)  # Rate limiting: 10 calls per second max
    
    return response.text

1.3 HTML Parsing and MD&A Extraction

The MD&A section is Item 7 in 10-K filings. The parsing logic handled three formats:

def extract_mdna(html_text):
    """Extract Item 7 (MD&A) from 10-K HTML."""
    soup = BeautifulSoup(html_text, 'html.parser')
    
    # Strategy 1: Find by document type tag
    # SEC filings use <TYPE> tags to mark sections
    doc_types = soup.find_all('type')
    for doc in doc_types:
        if 'EX-13' in doc.get_text() or 'EX-21' in doc.get_text():
            continue  # Skip exhibits
        text = doc.get_text()
        if 'MANAGEMENT' in text.upper() and 'DISCUSSION' in text.upper():
            return clean_text(text)
    
    # Strategy 2: Find by section headers
    headers = soup.find_all(['h1', 'h2', 'h3', 'b', 'font'])
    for i, header in enumerate(headers):
        text = header.get_text().upper()
        if 'ITEM 7' in text or 'MANAGEMENT' in text and 'DISCUSSION' in text:
            # Extract text until next major section
            return extract_until_next_item(soup, i)
    
    # Strategy 3: Regex pattern matching for plain text filings
    import re
    pattern = r'ITEM\s*7\.?\s*MANAGEMENT.*?DISCUSSION.*?(?=ITEM\s*8|$)'
    match = re.search(pattern, html_text, re.DOTALL | re.IGNORECASE)
    if match:
        return clean_text(match.group(0))
    
    return None  # Failed to extract

1.4 Sentence Segmentation and Output Format

After extracting MD&A text, the pipeline split it into sentences and counted words:

import nltk
nltk.download('punkt')

def process_mdna(text, ticker, fiscal_year, accession_number, cik, gvkey):
    """Segment MD&A into sentences and generate summary statistics."""
    sentences = nltk.sent_tokenize(text)
    words = text.split()
    
    # Filter out boilerplate sentences (short sentences, common phrases)
    kept_sentences = [s for s in sentences if len(s.split()) > 5]
    
    output = {
        'ticker': ticker,
        'fiscal_year': fiscal_year,
        'accession_number': accession_number,
        'cik': cik,
        'gvkey': gvkey,
        'company_name': get_company_name(ticker),
        'mdna_total_sentence_count': len(sentences),

After pulling raw Compustat data, the script calculated derived control variables:

# Calculate derived variables
comp_df['ROA'] = comp_df['ni'] / comp_df['at']

2.4 Future Variables (Realized)

Forward-looking control variables were constructed using groupby and shift:

# Sort by gvkey and fyear to ensure correct ordering
comp_df = comp_df.sort_values(['gvkey', 'fyear'])

# Future ROA: next year's realized ROA
comp_df['future_ROA'] = comp_df.groupby('gvkey')['ROA'].shift(-1)

# Future sales growth
comp_df['future_sales_growth'] = comp_df.groupby('gvkey')['sales_growth'].shift(-1)

# Future earnings growth: (NI_t+1 - NI_t) / abs(NI_t)

    comp_df.groupby('gvkey')['ni'].shift(-1) - comp_df['ni']

# Alias for regression team

2.5 Winsorization

All ratio variables were winsorized at 1% and 99% to handle outliers:

def winsorize_series(s, lower=0.01, upper=0.99):
    """Winsorize a pandas Series at specified percentiles."""
    q_low = s.quantile(lower)
    q_high = s.quantile(upper)
    return s.clip(lower=q_low, upper=q_high)

# Apply to all ratio variables
ratio_vars = ['ROA', 'sales_growth', 'future_sales_growth', 
              'future_earnings_growth', 'leverage', 'tobin_q']

for var in ratio_vars:
    comp_df[f'{var}_winsorized'] = winsorize_series(comp_df[var])

3. Critical Data Cleaning Challenges

3.1 Challenge 1: Fiscal Year Alignment

Problem Discovery

The fiscal year alignment problem affected 42 companies with non-December fiscal year ends. The core issue is a mismatch between how NLP and Compustat define "fiscal year":

NLP perspective:

  • fiscal_year comes from the accession number
  • Example: BF-B filed in 2019 → fiscal_year = 2019
  • This represents the calendar year when the 10-K was filed

Compustat perspective:

  • fyear is the fiscal year START year for Jan-May FYE companies
  • Example: BF.B fyear=2018 → datadate=2019-04-30
  • This represents FY2019 (May 2018 - April 2019)

The Misalignment:

  • NLP says BF-B 2019 = filed in 2019
  • Compustat says BF.B fyear=2018 = FY ended April 2019
  • Correct match: NLP 2019 ↔ Compustat fyear=2018
  • Previous WRONG fix: Added +1 → matched to fyear=2020 (FY2021, 2 years ahead!)

Verification with BF-B

NLP:        fiscal_year=2019, accession=19 (filed in 2019)
Compustat:  fyear=2018, datadate=2019-04-30 (FY May 2018 - Apr 2019)
            fyear=2019, datadate=2020-04-30 (FY May 2019 - Apr 2020)
            
Correct:    NLP 2019 → Compustat fyear=2018 → FY2019 data
Previous:   NLP 2019 → Compustat fyear=2020 → FY2021 data (WRONG!)

Fix Implementation (fix_fiscal_year_correct.py)

def fix_fiscal_year_alignment(nlp_df, controls_df):
    """
    Correct fiscal year alignment for non-December FYE companies.
    
    For Jan-May FYE: controls_fyear = nlp_fiscal_year - 1
    For Dec FYE:     controls_fyear = nlp_fiscal_year (no change)
    """
    
    # Identify non-December FYE companies
    # These have fiscal year end months 1-5 (January through May)
    non_dec_fye = controls_df[controls_df['fmonth'].isin([1,2,3,4,5])]['gvkey'].unique()
    
    # Create mapping
    nlp_df['controls_fyear'] = nlp_df['fiscal_year'].copy()
    
    # For non-December FYE companies, subtract 1
    mask = nlp_df['gvkey'].isin(non_dec_fye)
    nlp_df.loc[mask, 'controls_fyear'] = nlp_df.loc[mask, 'fiscal_year'] - 1
    
    # Now merge with controls using controls_fyear = controls.fyear
    merged = nlp_df.merge(
        controls_df,
        left_on=['gvkey', 'controls_fyear'],
        right_on=['gvkey', 'fyear'],
        how='left'
    )
    
    return merged

Deduplication Side Effect

The fiscal year fix revealed two duplicate rows:

  • CRM FY2022: Two filings with same accession number
  • SMCI FY2019: Duplicate entry

These were deduplicated by keeping the first occurrence.

3.2 Challenge 2: Dual-Class Share Deduplication

Problem Discovery

Three companies have dual-class share structures with separate tickers but identical filings:

Secondary (Drop) Primary (Keep) Reason
GOOG GOOGL GOOGL has complete gvkey/cik
FOX FOXA FOXA has complete gvkey/cik
NWS NWSA NWSA has complete gvkey/cik

Problem: Both classes share the same accession_number, creating duplicate rows in the panel.

Fix Implementation (fix_dual_class_and_gvkey.py)

def remove_dual_class_duplicates(df):
    """
    Remove dual-class share duplicates.
    Keep primary class, drop secondary class.
    """
    
    dual_class_pairs = [
        ('GOOG', 'GOOGL'),   # GOOGL is primary
        ('FOX', 'FOXA'),     # FOXA is primary
        ('NWS', 'NWSA'),     # NWSA is primary
    ]
    
    rows_before = len(df)
    
    for secondary, primary in dual_class_pairs:
        # Find rows with secondary ticker
        mask_secondary = df['ticker'] == secondary
        
        # Check if corresponding primary exists with same accession
        for idx in df[mask_secondary].index:
            accession = df.loc[idx, 'accession_number']
            fiscal_year = df.loc[idx, 'fiscal_year']
            
            # Check if primary exists for same filing
            mask_primary = (
                (df['ticker'] == primary) & 
                (df['accession_number'] == accession)
            )
            
            if mask_primary.any():
                # Drop secondary row
                df = df.drop(idx)
                print(f"Dropped {secondary} for {accession} (kept {primary})")
    
    rows_after = len(df)
    print(f"Removed {rows_before - rows_after} dual-class duplicate rows")
    
    return df

Result: Removed 21 rows (7 years × 3 pairs), reducing panel from 3359 to 3338 rows.

3.3 Challenge 3: Missing gvkey/cik for Hyphenated Tickers

Problem Discovery

Two companies use hyphens in NLP data but dots in Compustat:

NLP Ticker Compustat Ticker Missing
BF-B BF.B gvkey, cik
BRK-B BRK.B gvkey, cik

This caused merge failures because the ticker strings didn't match.

Fix Implementation

def fix_ticker_mapping(df, controls_df):
    """
    Fix ticker mapping for hyphenated tickers.
    """
    
    ticker_fix_map = {
        'BF-B': 'BF.B',
        'BRK-B': 'BRK.B'
    }
    
    # Create lookup column with fixed tickers
    df['tic_lookup'] = df['ticker'].replace(ticker_fix_map)
    
    # For each problematic ticker, fill gvkey and cik from controls
    for tic in ['BF-B', 'BRK-B']:
        lookup_tic = ticker_fix_map[tic]
        
        # Get gvkey/cik from controls
        ctrl_info = controls_df[
            controls_df['tic'] == lookup_tic
        ][['gvkey', 'cik']].drop_duplicates()
        
        if len(ctrl_info) == 1:
            gvkey_val = ctrl_info['gvkey'].iloc[0]
            cik_val = ctrl_info['cik'].iloc[0]
            
            # Fill in main dataframe
            mask = df['ticker'] == tic
            df.loc[mask, 'gvkey'] = gvkey_val
            df.loc[mask, 'cik'] = cik_val
            
            print(f"Filled {tic}: gvkey={gvkey_val}, cik={cik_val}")
    
    return df

Verification:

  • BF-B: gvkey=2435, cik=14693 (7 rows filled)
  • BRK-B: gvkey=2176, cik=1067983 (7 rows filled)

After fix: 3338 rows with 100% complete gvkey and cik.

4.2 Momentum and Volatility Calculation

def calculate_momentum_12m(returns_df):
    """
    Calculate 12-month momentum (t-12 to t-1, skipping most recent month).
    Uses log returns then exponentiates.
    """
    # Convert simple returns to log returns
    returns_df['log_ret'] = np.log1p(returns_df['ret'])
    
    # Calculate 12-month cumulative log return
    momentum = returns_df.groupby('permno')['log_ret'].rolling(window=12, min_periods=10).sum()
    
    # Convert back to simple return space
    momentum = np.expm1(momentum)
    
    return momentum

def calculate_volatility_12m(returns_df):
    """
    Calculate 12-month return volatility (standard deviation).
    """
    volatility = returns_df.groupby('permno')['ret'].rolling(window=12, min_periods=10).std()
    return volatility
